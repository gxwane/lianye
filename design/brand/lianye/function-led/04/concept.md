# 04｜共横接页

日期：2026-10-05

领域：名称本身成为识别图形；定制中文字体、字形连接

状态：文字概念登记，等待主 agent 审核后才制作视觉稿。尚未验证读字与小尺寸表现。

## 1. 方向名与具体结构

**方向名：共横接页。** 把「连页」做成上下阅读的定制字标，两个字沿同一竖直轴接续；「连」在上，「页」在下。主体就是可读的两个汉字，无外加图标、边框或底板。

关键改变不是加粗或手写连字，而是**让上字「连」的辶末捺，与下字「页」的首横共用同一段笔画**。两个通常分开的字框，沿这一共同横笔发生真实重合，接成一个长字标；同一界面位置只留一根横笔。辶左侧仍保留点和折笔，末捺由左侧稍有起伏的承托段过渡为水平段；右侧水平段同时成为「页」的顶横。不得把末捺画成箭头、折带或尖锐闪电。

用于后续造型的初始比例约束：

- 总体约宽 1、高 1.8；上、下字的字面宽度基本相等。上字字框与下字字框在接横处重合约 0.12 个字高，避免简单地把两个常规字体上下排放。
- 共横位于整体高度的约 48%；上字辶末捺的右侧至少半个字宽，与下字首横完全重合，成为一根实笔，不能画双线或用两种颜色分出两层。
- 上方保留「连」完整的「车」结构和辶的点、折、捺。车的中竖止于共横之上，留出可读的空隙，不贯穿到下字。
- 下方「页」保留首横下的短撇、贝部外框及下方撇点。它的首横已经由共横承担，不再另添一根；贝部仍按汉字结构留开底部，不能封成普通文档框。短撇与共横留正常笔间隙，避免读成「贡」或「贝」。
- 笔画采用均衡、略有宽扁特征的定制黑体骨架，直切末端；只在辶转折保留很小的曲率。风格来自字形结构与共笔关系，不靠渐变、立体或材质。

先用单色建立结构。后续如获准出图，应同时查看完整字标与小尺寸缩略稿；不提前承诺它能用作 24 px 图标。

## 2. 可见的功能证据与主动作

**主动作：越过一屏，把接续内容接成一张长图。**

图上可以直接指出的证据是「共横」及其上下两个连续字域：上半部的画面内容已经结束在这根横笔上，下半部继续向下展开；上半部的末笔，同时成为下半部的起笔，两个画面在接合处没有重复边界。这是把相邻截取结果沿共同区域对接、只保留一次的结构转译。

「页」下方保留完整贝部和撇点，表明接合之后还有完整下段；字标的细长竖向整体对应跨屏结果。名称在这里同时完成识别与功能表达，不再在普通字标旁另放一个拼接符号。

**证据的限度：** 静态字标不能单独表现 Android 的自动操作；共横表达接合与接续，比表达具体的滚动速度更清楚。它也不是流程图，没有宣称任意页面都能成功拼接。功能关系是设计推断，必须通过实图确认：若实图只像普通竖排文字、看不出共用边界，主概念应退回修改，不用说明文字补救。

## 3. 误认与品类风险

字标本身已经是名称；若不另加普通字体的名称说明，人仍应先读出「连页」。主要风险是被看成出版社、排版工具或书店，其次是把合笔后的整体当成一个不认识的汉字或篆刻合文。

控制办法：保留现代黑体的车、辶、页部件；上下字域各自留足内空；不加印章外框、朱红底、书脊、翻页角或纸张层叠。共横必须明显是一根现代几何横笔，两字其余部件不能为了连成一体而全部相接。下字短撇与贝部撇点不得省略；上字车的撇折不得简化成矩形里的加号。

这里没有独立于名称的无字图形版：若把汉字拿掉，识别主体也随之消失。它的代价是对中文阅读更依赖，不能把抽掉汉字的几何轮廓假称为已成立的国际化符号。

## 4. 重复风险、小尺寸与单色风险

仅依照 brief 的领域与淘汰规则评估；未读取其他组或旧稿。

- 与 02「对位、重叠消除与接合」在功能上有相邻关系，但主体必须保持为两个明确可读的汉字，不能演变为两张独立矩形的重叠图。与 07「内容与版式」的区别在于不加入文本行、对话气泡或文章版式。与 09 的风险是竖排合字容易像印记，因此禁止外框和篆刻笔法。
- 与 brief 淘汰的普通粗体汉字的区别，需要由**辶末捺与页首横的真实共笔**成立；若只是字距压紧或加粗，应直接淘汰。整体不得转成 S/Z 折带、闪电、门洞、数字 0 或递增三横条。
- 小尺寸最先受损的会是「连」车部的撇折、辶点与折的分离，以及「页」的短撇。两字如果为了图标宽度被横向压缩，会从可读名称变成密集纹样。初稿应保持正常字宽，以总高容纳连续结构；审核需检查 64 px 与 32 px 的正反色截图，允许判断这个方向只能作为品牌字标，而不是强行宣布小图标可用。
- 单色结构本身不依赖颜色；接合处必须只有一根笔画。反白时共横上下的细空隙可能被视觉膨胀吞掉，需要单独做光学校正，不能把正色稿机械反相后直接交付。

## 5. 官方参考来源与提炼原则

已通过 web 搜索并打开下列官方页面。参考的是字标构造与验证原则，不照描字母、条纹或现成品牌轮廓。

**IBM：[IBM Design Language — 8-Bar](https://www.ibm.com/design/language/ibm-logos/8-bar/)。** 官方规范展示字标网格，并说明正色与反白版本会调整条带厚度和字腔尖角，以维持光学一致性。**本概念的设计推断：** 复杂名称可以靠统一的结构规则形成识别；共横两侧及字内空隙应做光学校正。这里只借鉴网格与正反色检查，不使用 IBM 的八条横纹、字母构形或配色。

**Mozilla：[Route One: Protocol 2.0](https://blog.mozilla.org/opendesign/route-one-protocol-2-0/)，及 [Arrival](https://blog.mozilla.org/opendesign/arrival/)。** 这是 Mozilla 官方记录的 2016—2017 年历史字标方案。它把网址语法嵌入名称，并在正式发布说明中明确这种字标关系指向互联网。**本概念的设计推断：** 名称可以成为承载产品关系的主体，不必让旁边的通用图标承担全部功能语义；对「连页」采用真实的笔画接合关系，而不是照用网址标点或技术代码。

两项推断都不是来源对「连页」的评价，也不构成可读性或功能识别已通过测试的证据。

## 6. 被淘汰的第二概念

**第二概念：长框页。** 横排「连页」；「连」保持约一个字高，「页」的贝部外框竖笔向下延长至约 1.6 个字高，内部撇点一起下移。把「连」辶的末捺延长，接到长「页」左边竖笔的中部，形成上方一屏已经结束、右边页面还向下延伸的字形。首横与短撇仍留在「页」顶部。

它的优点是伸长的页部外框更容易提示长图，且横排可读顺序直接；但要让跨屏感足够明显，就必须显著拉长「页」的外框和下部笔画，破坏两字重心与常规识读。「页」容易退化成带头部的文档图标；辶接框又可能读成托盘或通用导出符号。若减弱延长，只剩普通字标加装饰尾线。因此淘汰，保留共横接页的完整字形与唯一接合笔。
