# 06｜补行成图

## 1. 方向名与具体结构
主概念「补行成图」。用八列、十二行的粗像素模数构成竖向长图，只用实心面、直角和阶梯，不显示格线。上部九行是已形成的图片，内部挖出右上两格见方的亮点，以及中下部宽四格的单峰阶梯山形，建立图片识别。最下方是一条等宽、两格高的新增带。主体与它之间留一格高的横缝，左侧两列已经接通，形成左端融为一体、右端正在补入的接缝。山形的落脚一级在新增带内按列接续，使它成为同一画面的一部分。轮廓纵长，只有底部发生一次变化。

## 2. 功能对应与可见动作
亮点与阶梯山形说明对象是图片，不声称应用只截风景。纵长比例说明结果越过普通单屏。下部宽条对应相邻截图去掉重复区后留下的新像素，而不是另一张完整卡片。左端消失的缝与右侧尚存的缝，表现新增条带并入既有结果；跨缝接续的山形证明上下属于同一幅图。主动作是向下补入、逐段成图，不另加滚动箭头、编辑工具或保存徽章。

## 3. 误认风险与控制
无名称时可能被看成像素绘画、图片修复或照片打印应用。上半部保持完整，像素不从四周散落；只在底边出现一条宽带，区别于碎片重建。取消折角、齿孔、镜头及打印机轮廓。仍有下载进度的误认风险，因此不使用百分比、渐变填充或重复横线；可识别的画面必须比接缝更显眼。

## 4. 重复与尺寸风险
与02接合主题语义邻近，但不画两框重叠或匹配角点，主体是同一栅格内的成像面与新增采样带。与01边界探索相邻，但不用取景四角。避开S/Z折带、闪电和递增三横条。小尺寸可能吞掉亮点、阶梯，令底缝变成污点；后续须检查24、32、48像素实稿，必要时减少阶梯级数。单色依靠负空间和局部连通，不靠颜色区分新旧；目前未验证缩小稿。

## 5. 官方来源与提炼原则
已搜索并打开[Microsoft应用图标设计指南](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-design)：建议用简单形状集中表现核心功能，以少量元素保持小尺寸轮廓。由此推断只保留图片与一次新增带。已搜索并打开[IBM图标设计规范](https://www.ibm.com/design/language/iconography/ui-icons/design/)：以像素网格控制比例、位置和重量，并按语义修正形状。由此推断粗像素应服务于累积，不能只当装饰。以上推断属于本稿判断，不照描官方图标或品牌形状。

## 6. 第二概念与淘汰理由
候选二「像素落幕」：完整长图在下方，上方五枚同大的方像素沿两列下落，最后两枚嵌入图顶；图内仍有亮点和阶梯。它与主稿的运动位置及轮廓不同。淘汰原因是离散像素易暗示AI生图、修复、压缩或游戏积木，不能表达每次只增加底部条带，还把向下滚动改成上方碎片降落。保留主稿，等待总审。
