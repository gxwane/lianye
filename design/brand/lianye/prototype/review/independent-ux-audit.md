# 连页原型独立体验评审

2026-10-06。独立查看 overview、首页/准备/目标/结果/裁剪/分享/保护/保存/失败/中断/小屏/暗色截图，阅读 prototype.js、model.cjs，以及现有 Android 的 PreFlightGuideBottomSheet、AboutBottomSheet、MainActivity 和中文 strings。未读取其他评审，未修改原型或应用，未作真机授权验证。

品牌方向可保留：暖白、石墨、烧橙和有留白的首页，让工具安静、容易识别。问题主要在流程：把授权说明、保存进度、保存成功、分享交接都做成需要处理的页面或弹窗，形成了过多「先看说明，再确认继续」。简化应减少用户要理解的状态和决定，同时保留真正的系统授权、当前内容保护和操作反馈。

| 节点 | 当前负担 | 建议 |
|---|---|---|
| 首次准备 | 三项能力/隐私说明，系统页再重复；成功后回首页再点「去截图」 | 保留一次简短说明和本机厂商路径。授权成功后接着显示侧边按钮，提示打开目标页面；不自动开始截取。 |
| 系统授权 | 原型自绘了无障碍确认和 Android 10 屏幕捕获确认 | 真实系统窗口必须保留；应用不要在每次授权前再加同义确认。只请求当前缺少的能力。 |
| 截取 | 「截取」→「结束」，另有已保留屏数 | 路径清楚，保留。自动结束后直接到结果；不用成功弹窗。 |
| 保存 | 保存过程弹窗 → 成功弹窗 → 完成/继续编辑；「保存并新建」还要再选一次新建 | 保存按钮内显示进度，结果页显示成功。已明确选「保存并新建/完成」时，保存成功直接兑现动作；失败则留在当前草稿。 |
| 返回/完成 | 返回保留草稿，「完成」清空草稿；同一屏两个退出动作含义相反 | 普通离开都保留草稿，取消未保存结果页的清空型「完成」。需要替换/清除未保存内容时才出现一次保护。 |
| 分享 | 应用自制三种目的地 →「已交给所选应用」→ 返回长图 | 直接调用系统分享面板。返回后留在结果页，草稿继续保留。交接不等于发送成功，也不等于已保存到相册。 |
| 停用服务 | 空闲时停用也弹确认 | 空闲时直接停用并反馈；保留草稿。运行中的状态应单独处理，不能用取消所有确认来代替。 |

新用户路径：**开始长截图 → 一次准备说明 → 必要的真实系统设置/授权 → 打开目标页面 → 侧边「截取」→ 自动结束或「结束」→ 检查，按需裁剪 → 保存/系统分享**。首次说明不是多余点击：跨应用截图权限容易让人不理解，短解释和准确入口可以减少错误。授权失败只在当前状态提供重试与帮助，不强迫重看整套说明。

高频用户路径：在目标页面直接点侧边「截取」；按钮隐藏时，从首页「去截图」恢复按钮并离开。能力仍有效时不再展示准备页。截取后检查/裁剪并保存，成功反馈留在结果页；接着分享或离开都无需再次确认。若要新建并替换未保存草稿，才问「先保存，还是放弃？」。

建议关键文案与时机：

| 状态 | 文案 / 动作 |
|---|---|
| 首次准备 | 「开启长截图」；「用无障碍服务截取画面、自动滚动。图片在本机处理。」；一条本机路径；「前往设置」 |
| 就绪 | 「打开要截取的页面，点侧边『截取』。」；首页主动作「去截图」 |
| 授权未完成 | 「截图服务未开启」；「前往设置」「开启帮助」 |
| Android 10 尚缺屏幕捕获能力 | 「还需允许屏幕捕获」；「继续授权」。是否再次请求以真实能力状态为准。 |
| 截取中 | 「已截取 3 屏」；侧边「结束」 |
| 结果 | 「长图」或现有「检查长图」；状态「未保存」「已保存至相册」；动作「裁剪」「保存」「分享」 |
| 保存中/成功 | 按钮「正在保存…」；完成后「已保存至相册」。只在内容再次编辑后恢复保存动作，避免重复导出。 |
| 保存失败 | 「保存失败，草稿已保留」＋「重试」。仅在知道原因时追加具体原因，不默认判断为空间不足。 |
| 替换未保存草稿 | 「当前长图未保存」；「新截图会替换当前草稿。」；「保存并新建」「放弃并新建」「取消」 |
| 截取中断 | 「截取中断，已保留 2 屏」；显示一次行内提示并允许检查、保存。 |

主流 Android 帮助确实遗漏。现有 PreFlightGuideBottomSheet 按厂商选择小米、OPPO、vivo、华为、三星和 AOSP 的路径，原型 prepare 没有厂商路径，restricted 仅有通用文字。恢复时不要列六套步骤：首次准备只显示检测到的本机路径；「开启帮助」中允许切换机型/查看通用入口。原有路径需在目标机型/版本上验证，不能把资源文案当成现时系统事实。受限设置页保留「打开应用信息」直达动作，避免要求用户另找桌面图标。About 中原有电池设置与 ADB 高级排障应保留为折叠帮助，常规路径不出现。

结果页去掉遮盖入口、遮盖编辑状态与相关教学文字，不将隐私能力变成另一项编辑功能。只留裁剪即可满足主要整理需求。撤销/重做在存在编辑时出现，顶部/底部定位在长图中有价值，不宜只为少按钮删掉。放大优先支持手势；保留必要的可访问替代入口。

裁剪截图中默认全图宽度很窄，四组百分比滑杆又占较多高度。优先让用户看清内容并拖动裁剪边界；全图概览用于定位，精确边界输入放在可展开控制中。不能只删滑杆却留下难拖动的缩略图，也不能只按点击数评价这种操作。

问题归属需区分：

- **设计问题**：保存/分享成功仍需确认；返回与完成语义相反；准备页重述能力；结果工具过多；裁剪控制比内容突出；熟悉用户仍反复看到宣传式标题。应在原型里先决定动作和信息层级。
- **原型实现与覆盖问题**：grant 固定回首页；save 总是打开 saved 弹窗；share 总是进入 shared 状态；厂商帮助和应用信息直达动作缺失。现有 Android 已调用系统分享面板，且保存并新建有后续动作，不能把原型的每次打断都归咎于现有 App。
- **状态模型问题**：model 仅用 saved 布尔值判断保护，撤销回已保存版本也会变成未保存；prototype 在每次截取结束后直接清除 projection。正式实现应按实际能力与保存版本判断，避免无谓重授权/重保存。分享后仍保护未保存草稿是正确的。

优先顺序：删除遮盖 → 恢复按设备提供的授权帮助 → 取消保存与分享的二次确认 → 统一离开时的草稿语义 → 简化裁剪与结果工具。视觉风格不需要推翻；把品牌表达主要留在首次首页，把任务页留给图片、状态和下一步动作。

## V2 独立复核

重新查看 prototype.js、model.cjs 与 06-result、07-crop、11-saved、12-draft、13-save-error、19-help。设计已可用于评审：遮盖已删除，结果明确保留裁剪/保存/分享；进度、成功和失败均为行内反馈；普通返回保留草稿，只有替换未保存内容才确认。首次授权后可延续任务，保存并新建不再要求确认第二次。裁剪默认内容可读，全图定位、还原与编辑内撤销仍保留。「查看」入口可发现，适合收纳放大和顶部/底部定位。按厂商提供的开启路径、完整路径、应用信息及高级排障均有入口；折叠没有丢失任务。系统页面与分享面板均按原型模拟理解，不据此判断真实系统适配。无需再增加说明或成功弹窗。

V2 初次复核发现 **1 个必要的实现问题：保存中允许替换草稿，旧异步回调会作用于新草稿**。save 禁用了当前页的裁剪/保存/分享，但返回后 new/discard-new 仍可执行；700ms 回调使用全局 s.draft。提取原文件 save/replaceDraft 函数并以模型重放「保存中→替换→新截一屏→旧回调完成」：普通保存把新草稿由 saved=false 错标为 true；保存并新建则将新草稿清空。此问题属于原型状态实现。

**处理结论：已解决。** 独立核对新建按钮、new handler 与 replaceDraft 的保存期守卫，以及 exportingState/exportingDraft 回调绑定；直接运行 `node design/brand/lianye/prototype/verify-save-race.mjs`，退出码 0。浏览器验证显示快速替换尝试后原四屏草稿正常保存，保存并新建期间禁止二次新建，后续一屏草稿仍保留且未保存。修复没有增加确认，也没有限制普通返回。本次独立复核没有剩余的必要问题，V2 可用于评审；真实系统适配仍应按应用实施阶段验证。
