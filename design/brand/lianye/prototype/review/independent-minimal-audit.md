# 连页原型：独立精简评审

评审范围：`overview.png`、`prototype.js`、`model.cjs`，以及现有应用的 `DeviceVendorDetector.kt`、`PreFlightGuideBottomSheet.kt`、`AboutBottomSheet.kt`、中文字符串。未读取其他评审，未修改原型或应用。以下是静态画面与代码审查，不代表真机测试。

**判断：视觉方向成立，功能和解释仍偏重；厂商帮助确实在原型中遗漏。** 保留已批准的名称、Logo 和配色。连页的边界应是“把可滚动页面截成一张能保存、分享的长图”。遮盖编辑已经越过这个边界；删掉它不会削弱核心任务。

暖白底、橙色强调、取景框插画和大标题有辨识度，首页单个主按钮也容易理解。负担集中在准备、编辑和保存环节，而不是整套视觉失去设计感。目标页面里的文章文字属于截图内容，不能当作应用说明冗余。

## 真实 OEM 能力与差距

现有实现按 `Build.MANUFACTURER` / `Build.BRAND` 的字符串匹配分为五组厂商和一个通用回退；没有按 Android 或厂商系统版本选路径。

| 代码实际归组 | 匹配范围 | 项目现有中文路径，末尾均为应用名 |
| --- | --- | --- |
| XIAOMI | manufacturer 包含 xiaomi / redmi，或 brand 包含 blackshark | 设置 → 更多设置 → 无障碍 → 通用 → 已下载的服务 |
| OPPO | manufacturer 包含 oppo / oneplus / realme | 设置 → 其他设置 → 无障碍 → 通用 → 已下载的应用 |
| VIVO | manufacturer 包含 vivo / iqoo | 设置 → 快捷与辅助 → 无障碍 → 已下载的服务 |
| HUAWEI | manufacturer 包含 huawei / honor，或 brand 包含 honor | 设置 → 辅助功能 → 无障碍 → 已安装的服务 |
| SAMSUNG | manufacturer 包含 samsung | 设置 → 辅助功能 → 已安装的应用程序 |
| AOSP | 其余设备，通用回退 | 设置 → 无障碍 → 已下载的应用 |

这证明项目有品牌分组帮助，不证明每个子品牌、新系统版本都已单独验证。荣耀没有独立路径，一加和 realme 也共用 OPPO 路径；不能据此声称所有新版系统入口相同。原组件已有“设置名称可能因系统版本不同而变化”的说明，应保留这一含义。

`PreFlightGuideBottomSheet` 会显示本机对应路径；Detector 还生成标准无障碍设置 Intent，并附带目标服务定位参数。这是尝试定位服务，不是每家系统都有专用直达入口，也不能保证厂商接受高亮参数。

原型的 `model.cjs` 没有 vendor 字段，`prepare` / `system` 页面也没有路径分支；因此六组提示和定位能力都未被表达。受限设置页只有通用说明，缺少现有“打开应用信息”的直接动作。原应用还把电池设置、复制 ADB 命令放在折叠的“高级排障”中，原型没有对应入口。

Android 10 的单独屏幕捕获分支仍在原型，没有完全丢失；但原型先开启无障碍再申请捕获，而现有 PreFlight 允许先捕获再继续无障碍。正式整合应按真实权限状态呈现下一步，不把模拟流程视为系统事实。现有字符串仍叫“长卷”，路径末尾应随正式更名使用“连页”。

## 功能删留

| 决定 | 范围 |
| --- | --- |
| 保留 | 自动滚动拼接、手动结束、长图检查、保存、系统分享；权限失败可重试，截取中断保留有效内容 |
| 保留但收轻 | 一个当前草稿；简单裁剪；隐藏侧边按钮与停用服务的区别；按设备显示授权帮助 |
| 删除 | 遮盖入口、遮盖编辑页、位置/宽高百分比、遮盖状态和使用说明中的相关文字 |
| 简化 | 裁剪以直接拖动边界为主，取消四条默认百分比滑杆；撤销/重置放进裁剪操作，不常驻结果页 |
| 删除重复步骤 | “正在保存”整页弹层、“已保存”二选一弹层、“已交给所选应用”确认弹层；停用这种可恢复动作不必再次问一次 |
| 保留必要保护 | 仅在明确丢弃或替换未保存草稿时确认；保存失败留在结果页提供重试，不假装已成功 |

结果页优先展示图片、裁剪、保存与分享。把会清理草稿的“完成”收成普通返回并保留草稿，避免用户误以为它等于保存；新建时再处理旧草稿。缩放和长图导航用常见手势及滚动提示承载，确保末尾可检查；当前四按钮浮动工具条不必一直占据图片。分享交给 Android 系统，不维护应用自有的聊天/邮件/文件选择器。高级排障保留在帮助深处，避免把普通用户带进 ADB。

## 简洁的帮助与反馈

1. **首页：** 一个主动作、一句功能说明、一处“本机处理”标记。已就绪、未授权、草稿三种状态各显示自己的下一步，不堆成问题列表。
2. **首次开启：** 用两行说明服务用途，加一条“本机设置路径”和“前往设置”。路径默认只显示当前设备；“找不到入口”再展开完整步骤或通用路径。不要让用户先选手机品牌。
3. **无法开启：** 由用户点“无法开启？”或遇到明确失败后显示。提供“打开应用信息”和“返回无障碍设置”；受限设置说明沿用项目已有保守措辞，不添加未经核实的新入口。
4. **如何截图：** 三句足够：“打开目标页面 → 点侧边截取，结束时停止 → 检查并保存”。服务易失效时再去高级排障。
5. **保存与分享：** 保存成功用短反馈“已保存到相册”，留在结果页；用户主动返回即可。新建前已选择“保存并新建”的，保存成功后直接继续。分享只说明已交给所选应用，不能承诺发送成功。

首次准备中的三块说明与首页、系统模拟页、设置页反复讲“本机处理 / 截取滚动 / 侧边按钮”，可以合并。真正该留下的文字是下一步、当前状态和失败恢复方法；必要授权说明保留一次。让设计感来自留白、图像占比和操作层级，不能靠把遇到授权障碍时唯一有用的厂商路径一并删掉。

建议实施顺序：删遮盖与重复确认 → 恢复本机厂商路径和直接排障动作 → 压缩默认文字、让图片占据结果页。这样可以同时变简单、减少误操作，并保住已有适配能力。

## V2 独立复核

复核 `prototype.js`、`device-help.cjs` 与 `19-help.png`、`02-prepare.png`、新版 `overview.png`；前文保留为 V1 评价。**V2 可以用于设计评审，没有需要重做的结构问题。** 主流程已收敛为截取、检查、裁剪、保存与分享：遮盖和百分比滑杆移除，撤销仅在裁剪中出现；保存成功留在结果页，返回保留草稿，替换未保存草稿才确认。功能边界符合这个小工具的任务。

准备页现在只有服务用途、本机路径和下一步；帮助页把三步用法与授权路径分开，完整路径和高级排障折叠。图片在结果页占据主要面积，查看工具按需打开，文字密度与视觉层级已取得合理平衡，不建议继续增加首页说明或新功能。

已用独立脚本逐项比较：`device-help.cjs` 的六条完整 OEM 路径与项目中文 `vendor_path_*` 一致，仅把应用名占位符换成“连页”。六组厂商帮助已恢复，应用信息、电池和 ADB 排障入口也已恢复。原型用厂商选择器模拟设备，不能据此证明真实自动识别、服务焦点定位或新版系统授权已验证；这些仍由 Android 实现和真机检查承担。系统页、后台开关和 ADB 命令的模拟呈现同样不是跨版本有效性的证据。

仅有两处收尾建议，均无需增加页面或问题列表：

1. 三步说明补回手动结束和检查结果：第二步可写“点侧边「截取」，自动滚动；可点「结束」”，第三步写“结束后检查，再保存或分享”。当前“到达底部后，保存或分享”漏掉了这两项已有行为。
2. 原 `AboutBottomSheet` 有“复制 ADB 命令”动作，V2 只有命令展示。若要完整继承高级排障，应在折叠入口内补回复制按钮；六组 OEM 路径本身没有缺失。

这是静态设计与源码复核，加一次路径一致性检查；没有把父任务报告的浏览器测试数量当成实机 OS 验证，也未读取其他报告或修改原型。
